# 编辑部协作台（独立网站版）

Cloudflare Pages + Functions + D1，静态前端 `index.html`，接口在 `functions/api/*`。

## 一次性搭建步骤

1. **建 D1 数据库**：Cloudflare 后台 -> Workers & Pages -> D1 -> Create database，随便起个名字（比如 `editorial-desk-db`）。
2. **建好表**：进这个数据库的 Console 标签页，把 `schema.sql` 的全部内容粘进去执行一次。
3. **建 Pages 项目**：Workers & Pages -> Create -> Pages -> Connect to Git，选这个仓库，Build 设置全部留空（没有构建步骤，Framework preset 选 "None"，Build output directory 填 `/`）。
4. **绑定数据库**：Pages 项目建好后 -> Settings -> Functions -> D1 database bindings -> Add binding，Variable name 填 `DB`，选第 1 步建的数据库。
5. 保存后 Cloudflare 会自动重新部署一次，之后打开 Pages 给的 `*.pages.dev` 网址就能用了。

## 以后怎么改

以后要改内容展示逻辑或加新功能，直接把新代码 push 到这个仓库的默认分支，Cloudflare 会自动重新构建部署，不需要重复上面 1-4 步。**除非新版加了新的数据表**（比如这次的任务接力/投票功能），那还要额外做一步：

- 去 Cloudflare 后台 -> D1 -> 这个数据库 -> Console，把最新的 `schema.sql` **全部内容**再粘贴执行一次。因为每个建表语句都写了 `IF NOT EXISTS`，已有的表和数据完全不受影响，只会把缺的新表建出来。

## 版本记录（页面底部会显示当前版本号）

页脚的版本号在 `index.html` 里手动维护（搜索 `VERSION` 变量），每次改完功能就顺手改一下，方便以后知道线上是哪个版本、出问题了要回滚到哪个版本。

真正能回滚的地方是 Cloudflare Pages 项目的 **Deployments** 列表：每次 push 到 GitHub 都会生成一条新的部署记录，出问题了可以直接在那里点某条旧记录 "Rollback to this deployment"，不需要改代码。页脚版本号只是方便肉眼对应"现在线上是哪次改动"。

- **v0.1.0**（首个可用版本）：账户注册 / 登录（用户名 + 邮箱 + 密码，密码服务器端加盐 PBKDF2 哈希存储）、多主题（"俱乐部"）+ 主题内昵称、留言板（主题创建者可删除任何人的留言，举报后的应急处理）。
- **v0.2.0**（当前版本）：新增任务接力清单、投票、活跃度排行三个标签页；页脚加上版本号/日期标记。

## 现在这版做了什么

- 账户注册 / 登录
- 多主题（"俱乐部"），主题内昵称
- 留言板，主题创建者可删除任何人的留言
- **任务接力清单**：按顺序排好任务，前一项完成前，后一项不能被认领（前后端都做了校验）；认领后可以标记完成或放弃；主题创建者可以删除任何一项（用于纠错）。
- **投票**：发起问题 + 若干选项，成员可以投票，再点一次同一个选项会取消投票；发起人或主题创建者可以结束/重新开放投票；票数和百分比实时可见。
- **活跃度排行**：按主题统计每个人的留言数、完成的接力任务数、投票数，加权算出一个总分排序（完成任务权重更高）。
